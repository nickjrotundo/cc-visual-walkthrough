ccwalk (CC Visual Walkthrough) - Privacy Policy

Effective 2026-08-31. Applies to the ccwalk Claude Code plugin and the cc-visual-walkthrough Python package.

The short version

ccwalk runs entirely on your machine and only talks to the web app you point it at. It has no telemetry, no analytics, no accounts, and it never sends anything to the developer.

What it captures

During a tour, ccwalk drives a browser through your own application and records what that application renders: screenshots, short videos, and text read from the page for assertions. Whatever your app displays during the tour (including any test data) ends up in the report. Reports are written locally under your project's reports/ directory and are yours to keep, share, or delete.

Credentials

Login credentials for tours are read from environment variables whose names you put in the config; the values live in your gitignored .env. Credentials and tokens are not written into reports or run metadata. The documentation recommends using a throwaway test account. When header-based auth is configured, the token is sent only to the origin of the app under test, never to third-party hosts the page loads.

Network access

  • The tour itself talks only to the app URL you configure.
  • ccwalk install-browsers downloads a browser from Playwright's official distribution servers - the one expected third-party download.
  • ccwalk serve binds 127.0.0.1 by default. Binding other interfaces, or publishing a report anywhere (for example this repository publishes its own demo report to GitHub Pages), is your action - remember reports contain screenshots of your app.

What the developer receives

Nothing. There is no phone-home of any kind. If you file a GitHub issue, that is governed by GitHub's terms, not this policy.
